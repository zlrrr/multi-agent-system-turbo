# 概要设计（HLD）：可切换的多 Agent 拓扑

> **特性 ID**：`003-switchable-topologies` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`design-hld.md`](./design-hld.md) · **上游**：[`plan.zh.md`](./plan.zh.md) v1.0.0 · **下游**：[`design-lld.zh.md`](./design-lld.zh.md)

## 1. 它处在哪个位置

```
service ──► orchestrator.Open(name) ──► Orchestrator.Run(ctx, *agent.State)
                                              │
                      ┌───────────────────────┼───────────────────────┐
                      ▼                       ▼                       ▼
                 角色（agent）           工具（受护栏约束）        State（共享）
```

`Orchestrator` 接口上下的一切都不改变。拓扑拿到的是一个已完全备好的 `State`：
诊断目标、症状、规则引擎已产出的确定性结论、本次运行获准使用的工具注册表、
模型 provider 与各项预算。当它没有事可做时便返回。

## 2. 可比性契约

五个彼此无法比较的拓扑，比两个能比较的更糟 —— 因为那样"选哪个"就只是装饰。
因此这份契约是本特性的一等产物，而不是测试套件里的细节。每个已注册拓扑都必须：

| # | 性质 | 它为何在此列 |
|---|---|---|
| 1 | 被收录 —— 出现在契约表中 | 靠"没被列进去"来规避契约，会让契约失效 |
| 2 | 在证据足以支撑时产出 ≥1 条假设与一段摘要 | 报告所需的最低产出 |
| 3 | 把每一次模型交互归属到角色 | 没有归属就无法分摊成本，转录也无法阅读 |
| 4 | 遵守步数预算，超限时记录截断 | 无界的拓扑无法在成本上做比较 |
| 5 | 某个域没有工具时仍能完成，并记录缺口 | 可比性必须在离线运行下依然成立 |
| 6 | 在相同状态上具有确定性 | 两次因调度而不同的运行，不构成实验 |
| 7 | 用两种语言自我描述，并说明**何时不该**选它 | 蒙着眼睛选，不叫选择 |
| 8 | 只引发只读工具调用 | 宪法第四条 |

第 2–6 条通过让每个拓扑跑同一套脚本化 mock 来检查；第 1、7、8 条是结构性检查。

## 3. 五种拓扑

| 拓扑 | 控制流 | 成本 | 何时选它 |
|---|---|---|---|
| `single` | 一个通才持有全部工具 | 最便宜；无分工、无反驳 | 建立基线时 |
| `supervisor` | 规划 → 并发的分域调查员 → 关联 → 批判 → 报告 | 中等；I/O 并行 | 默认；证据面广、一遍过 |
| `plan-execute` | 规划 → 执行一个目标 → 依结果重新规划 → … → 关联 → 批判 → 报告 | 顺序、自适应；一查即中时便宜，否则更贵 | 首个检查很可能就能定论，或证据获取代价高 |
| `debate` | 调查 → 关联 → 多个 advocate 并发论证相互竞争的立场 → 裁决者判定 → 报告 | 最贵；每个立场一次 advocate 调用 | 两个原因能解释同一份证据，且选错代价很高 |
| `blackboard` | 当共享状态使某贡献者具备条件时它才行动，按轮推进，直到某一轮毫无贡献 | 可变；随现有证据自适应 | 证据到达不均匀，固定脚本会白白浪费调用 |

差异只在控制流。它们读的是同一份确定性结论、用的是同一批受护栏约束的工具、
写的是同一个 `State`。

## 4. 两个真正新的想法

**自适应重规划。** `plan-execute` 是唯一一个"下一步动作取决于上一步返回结果"的拓扑。
这正是它的全部主张：它可以提前收手，也可以改变方向。两者都必须可观测，
否则该主张不可证伪 —— 因此计划及其每一次修订都会被记为笔记，
且一致性契约会检查"首个目标即可定论"的运行确实短于"首个目标不能定论"的运行。

**数据驱动的控制。** `blackboard` 没有脚本。一个确定性的控制组件按黑板状态评估每个贡献者的
前置条件，并运行具备条件的那些。循环在某一轮什么都没改变时结束 ——
这是状态的性质，不是计数器的性质。那些"具备条件"的谓词就是设计本身；
它们在 LLD 中逐条写明，且每一条都有测试。

## 5. 本特性刻意不做的事

- **打分。** 比较成本是公允的；在没有 case 语料库的情况下宣布赢家则是无依据的断言，
  宪法禁止这样做（第九条）。
- **锦标赛执行器。** 把同一个案例跑过五个拓扑，就是把 `mas diagnose --topology` 放进循环。
  在还没有可供打分的语料库之前先把它包装成命令，等于先造接口、后造被接的东西。
- **按 Agent 的模型路由。** 与本特性正交，混进来只会污染本特性想促成的那场比较。
