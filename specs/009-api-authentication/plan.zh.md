# 实施计划：HTTP API 的认证与授权

> **特性 ID**：`009-api-authentication` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`plan.md`](./plan.md) · **上游**：[`spec.zh.md`](./spec.zh.md) v1.0.0 · **下游**：[`design-hld.zh.md`](./design-hld.zh.md)

## 1. 思路

有两个决策承载了这个特性。机制本身反而是容易的部分。

**如何处理现存的"默认开放"。** 今天的 API 未经认证，
因此任何答案都会打破点什么：强制要求凭据，会打破笔记本上的 `mas serve` 与 `make demo`；
而让它可选，则意味着一位忘了配置的运维人员会发布一个开放的 API，
并从别人那里得知这件事。

答案来自这两种情况之间**真正的**差别 —— 不是有没有设某个开关，
而是**这个套接字能被谁访问到**。回环监听本就受主机保护；
`0.0.0.0` 监听则不受任何东西保护。因此，这个要求挂在地址上：

- 回环 → 什么都不要求，什么都不变，demo 与现有全部测试照常可用；
- 其他任何地址 → 必须有认证，否则进程拒绝启动。

没有人需要记住一个开关，也没有人的笔记本会被打破。
运维人员唯一必须做的那件事，恰恰就是那件已经变得危险的事。

**明文连接上的一个 token 值多少钱。** HTTP 上的 Bearer 认证，
就是一份放在线路上的凭据；把它就这么发布出去，
等于造出一个看起来安全、实则不安全的东西。
但要求服务端自己终止 TLS，对最常见的 Kubernetes 部署形态又是错的 ——
那里已经有一个 ingress 在做这件事。

因此，主机之外的明文是被拒绝的，**除非运维人员声明由代理终止 TLS** ——
这是一个他们必须亲手写下的键，含义有文档说明，而工具本身无法验证它。
这是诚实的做法：它记录的是只有运维人员才知道的事实，
而不是去猜，也不是假装这个问题不存在。

**机制**在这两点定下来之后就很小，且沿用护栏的先例：
一个中间件、默认拒绝、一张"路由 → scope"的表、
用 `crypto/subtle` 比较 token，以及一个结构性测试保证任何处理函数都无法自行授权。

## 2. 设计决策

| ID | 决策 | 理由 |
|---|---|---|
| D-1 | 这个要求挂在监听地址上，而不是挂在某个开关上 | 笔记本场景与暴露场景的差别在于"套接字能被谁访问到"；让运维人员再声明一次，只是会被跳过的仪式 |
| D-2 | 拒绝启动，而不是发出警告 | 启动时的警告只会被读一次，而那份日志没人在看。失败必须发生在有人正在看的那一刻 |
| D-3 | 只用来自配置密钥的 Bearer token | OIDC 与 JWT 需要引入依赖，或部分地重新实现一个 —— 而"部分实现的 JWT 校验器"是一个有着友好名字的漏洞 |
| D-4 | 两个 scope：`read` 与 `diagnose` | `POST /diagnoses` 会花钱并读取生产系统；一个看板两者都不需要。再细的拆分就是按目标划分，那属于 P3-3 |
| D-5 | 主机之外的明文仅在显式 `terminated_by_proxy` 之后才允许 | 工具看不见那个代理。运维人员的声明是唯一诚实的输入，而"亲手写下它"就是那份确认 |
| D-6 | `/healthz` 与 `/readyz` 保持匿名；`/metrics` 不是 | 一个需要凭据的存活探针，会在凭据出问题时一起失败。而指标中带有目标名与运行次数 |
| D-7 | 一个中间件、默认拒绝、一张路由表 | 与安全护栏同形，理由也相同：会自行授权的处理函数，总有一天会忘记这么做 |
| D-8 | 把主体记录到运行上 | "是谁请求的"是"授权有意义"的另一半 |

## 3. 风险

| ID | 风险 | 缓解 |
|---|---|---|
| RSK-1 | 新增了一个路由，却没有人给它配 scope | 默认拒绝：未登记的路由一律拒绝，并由结构性测试断言每个已注册路由都有对应条目 |
| RSK-2 | token 经由某条错误路径进入日志 | `Secret` 本就拒绝打印；并由测试断言该 token 不出现在任何日志、任何错误响应体与任何被渲染的配置中 |
| RSK-3 | 地址规则被"代理监听回环"绕过 | 按构造属于范围外：回环之前的代理是运维人员的部署，而 `terminated_by_proxy` 正是他们声明这件事的地方 |
| RSK-4 | 常数时间比较被提前的长度检查破坏 | 对双方的定长摘要使用 `subtle.ConstantTimeCompare`，从而长度永远不产生分支 |

## 4. 实施顺序

1. 配置：token、scope、TLS，以及加载时的校验。
2. 启动规则：哪些监听方式会被拒绝，以及为什么。
3. 中间件：认证、授权、审计。
4. 运行记录上的主体。
5. `mas doctor` 报告暴露面；双语文档。
