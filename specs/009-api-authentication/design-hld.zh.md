# 概要设计（HLD）：HTTP API 的认证与授权

> **特性 ID**：`009-api-authentication` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`design-hld.md`](./design-hld.md) · **上游**：[`plan.zh.md`](./plan.zh.md) v1.0.0 · **下游**：[`design-lld.zh.md`](./design-lld.zh.md)

## 1. 它位于何处

```
                      ┌─ /healthz、/readyz ──────────────────► 处理函数
                      │  （按设计即匿名）
  请求 ──► mux ───────┤
                      └─ 其余全部 ──► 授权 ──┬──► 处理函数
                                        │     │    （主体放入 context）
                                  路由 → scope │
                                  token 表     └──► 401 / 403 + 错误码
                                        │
                                     审计日志
```

新增的只有一个方块，它位于路由与"除健康检查以外的每一个处理函数"之间。
这与安全护栏同形，理由也相同：会自行授权的处理函数，
总有一天会被复制走，而检查不会跟着一起走。

还有第二样新东西，它不在这张图上，因为它只发生一次、且从不在请求期间发生：
**准入**。在监听器打开之前，配置会与它即将绑定的地址一并被审视，
而一个会把"未认证的"或"凭据以明文传输的" API 暴露到主机之外的配置，会让进程停下。

## 2. 挂在地址上的那条规则

今天的 API 是开放的，因此任何改动都会打破点什么。
处处强制凭据，会打破笔记本上的 `mas serve`、`make demo` 与测试。
让凭据可选，则意味着忘了配置的运维人员会发布一个开放的 API。

出路在于注意到：这两种情况的差别不在意图 ——
而在于**这个套接字能被谁访问到**：

| 监听地址 | 认证 | TLS | 结果 |
|---|---|---|---|
| 回环（`127.0.0.1`、`[::1]`、`localhost`） | 不要求 | 不要求 | 启动；什么都不变 |
| 其他任何地址 | **必需** | —— | 没有它就拒绝启动（`MAS-7010`） |
| 其他任何地址 | 已配置 | 缺失，且未声明代理 | 拒绝（`MAS-7011`） |
| 其他任何地址 | 已配置 | 已提供，或已声明代理 | 启动 |

没有人需要为了在笔记本上安全而设某个开关，
也没有人会因为忘了设某个开关而在笔记本之外不安全。
这项检查在准入阶段运行并让进程停下，因为启动时的警告只会被读一次、
而那份日志没人在看；而一次拒绝，会在有人正在看的那一刻被读到。

明文那一行需要它自己的理由。HTTP 上的 Bearer token 就是一份放在线路上的凭据，
因此发布一个没有 TLS 的 Bearer 认证，等于造出一个看起来安全、实则不安全的东西。
但要求服务端自己终止 TLS，对其大多数用户所处的部署形态又是错的 ——
那里已经有一个 ingress 在做这件事。工具看不见那个 ingress。
所以它选择去问：声明了 `terminated_by_proxy` 的运维人员，
记录下的是只有他们才知道的事实，而"亲手写下它"就是那份确认。

## 3. Scope，以及为什么恰好是两个

`read` 与 `diagnose`，而这个划分并不随意。
`POST /api/v1/diagnoses` 会花掉模型 token 并读取生产遥测；
其余每个路由读取的都是已经算好的东西。
一个渲染最近一次诊断的状态页需要后者，而绝不该拥有前者 ——
可今天，要给它任何东西，就只能把一切都给它。

更细的授权 —— 某个 token 只能诊断**这些**目标 —— 是刻意缺席的。
那需要一套租户模型，而那属于 P3-3 的多租户注册表。
在这里做半套，会产出一个"看起来像租户隔离、实则不是"的按目标检查，
而第一个据此行事的人，会对自己手上有什么产生误解。

两个方向上都默认拒绝：没有 scope 条目的路由一律拒绝；
配置中写了本版本不认识的 scope 的 token，会在加载时失败，而不是被忽略。
一个被忽略的 scope，是一次运维人员以为自己已经授出的授权。

## 4. 是谁请求的

没有归属的授权只是半个特性。运行记录已经写明了诊断了什么、什么时候、
用哪种拓扑、花了多少；从此它还会写明**是谁请求的** ——
取自已认证的主体，而不是取自客户端可以自行设置的任何东西。

这闭合了问题陈述所打开的那个环：当某次诊断事后被发现代价高昂、
或读取了它本不该读取的系统时，终于有东西可供查看。
这也是为什么审计日志记录的是"判定"而不只是"失败"——
一份只显示拒绝的报告，回答不了"这是谁跑的"，
而事后真正被问到的正是这个问题。

## 5. 刻意不做的事

- **不接身份提供方。** OIDC 与 JWT 都需要本项目不打算引入的依赖，
  或者一次部分的重新实现 —— 而"部分实现的 JWT 校验器"是一个有着友好名字的漏洞。
  token 是配置，而配置正是运维人员本就在管理密钥的地方。
- **不做运行时 token 管理。** 通过 API 创建与吊销 token，
  会让这个 API 变成一个凭据存储 —— 那是另一个产品，带着另一套义务。
- **不做限流。** 它值得有，但属于另一个关注点；
  一次运行的预算已经限定了单个调用方在一次诊断中能花多少。
- **不给 CLI 加认证。** 它以运维人员的身份、用运维人员自己的配置与凭据运行。
  给一个本地二进制加登录，是一场背后没有任何边界的仪式。
