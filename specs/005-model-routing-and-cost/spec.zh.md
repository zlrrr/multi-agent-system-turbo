# 特性规格：模型路由与如实的成本核算

> **特性 ID**：`005-model-routing-and-cost` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`spec.md`](./spec.md) · **上游**：[`docs/zh/project-goals.md`](../../docs/zh/project-goals.md) v1.1.3
> **宪法**：`.specify/memory/constitution.zh.md` v1.0.0 · **下游**：`plan.zh.md`

## 1. 问题陈述

M2 还剩两项，而它们其实是同一个问题的两端。

**路由只做了一半。** `llm.per_agent` 已能按角色覆盖**模型**与**温度**，
Agent 循环也确实遵循它。它做不到的是切换 **provider**：
一位希望"抽取跑在本地 OpenAI 兼容端点、关联跑在 Anthropic"的运维人员，
根本无从表达 —— 尽管 provider 接口当初正是为了让这件事可替换而设计的。
接缝在，却没有任何东西够得着它。

**成本管线通了，却从未被测量。** `Usage.CostUSD` 从 provider 一路穿过运行记录直到报告 ——
而没有任何 provider 会给它赋值，因此它恒为 0。
今天这一点被渲染器里的 `> 0` 判断掩盖住了：报告会省略这一行，而不是打印 `$0.0000`。
那是**碰巧**如实，而且离"变得不实"只差一次粗心的改动 ——
一份声称本次运行没花钱的报告，比一份什么都不说的报告更糟，因为运维人员会相信它。

两者是连着的。特性 003 让拓扑之间可比，演示也会打印各自的花费 ——
以模型调用数与工具调用数计，因为只有这些数字是真实的。
路由是改变成本的那根杠杆；而成本是判断"拉这根杠杆是否有用"的依据。
只发布其中一个，另一个就用不起来。

## 2. 用户与场景

| 角色 | 目标 | 触发 |
|---|---|---|
| 平台工程师 | 让抽取跑在廉价本地模型上、判断跑在强力托管模型上 | 成本评审 |
| SRE | 看清一次诊断花了多少，以及是哪个角色花掉的 | 一次昂贵的运行之后 |
| 研究者 | 在结论之外，也按成本比较拓扑 | 选定默认拓扑时 |
| 没有价目表的运维人员 | 不要在什么都没定价的情况下被告知本次运行花费 `$0.00` | 任何一次运行 |

## 3. 范围

### 范围内
- 在既有的模型与温度之外，支持按角色选择 **provider**。
- 把模型价格作为**配置**，并据此计算成本。
- 一个明确的**未定价**状态，且在任何地方都绝不被渲染成 0。
- 按角色的核算：调用数、token、墙钟时间与成本，归属到花掉它们的那个角色，
  并出现在报告与运行记录中。
- 双语文档，含"如何为模型定价"以及"不定价会怎样"。

### 范围外
- 内置价目表。价格会变、随合同与区域而异，
  而一个看起来权威的过期数字，比没有数字更糟。
- 以货币为单位的预算强制。运行已有 token、步数与墙钟预算；
  一个由运维人员提供的价格算出来的成本上限，等于把安全控制建在未经校验的输入之上。
- 自动选模。按预估难度挑模型是一项优化，而本项目还没有可用于评估它的语料库（M3）。

## 4. 功能需求

| ID | 需求 | 优先级 | 验收信号 |
|---|---|---|---|
| FR-001 | 角色必须能指定不同于本次运行默认值的 provider，并带有各自的凭据与端点 | P0 | `TestPerRoleProviderIsUsed` |
| FR-002 | 一次运行所需的每个 provider 都必须只打开一次并复用，且在运行结束时关闭 | P0 | `TestProvidersAreOpenedOnceAndClosed` |
| FR-003 | 无法打开的按角色 provider 必须在任何工作开始之前、以错误码在准入阶段失败 | P0 | `TestUnopenableRoleProviderFailsAdmission` |
| FR-004 | 成本必须依据已配置的按模型价格计算 | P0 | `TestCostIsComputedFromConfiguredPrices` |
| FR-005 | 未配置价格的模型必须使本次运行的成本成为**未知**，而绝不是 0 | P0 | `TestUnpricedModelMakesCostUnknown` |
| FR-006 | 对于成本未知的运行，报告不得展示任何成本数字；必须写明其未定价 | P0 | `TestUnpricedRunSaysSoInBothLanguages` |
| FR-007 | 用量必须按角色归属：调用数、输入与输出 token、墙钟时间与成本 | P0 | `TestUsageIsAttributedPerRole` |
| FR-008 | 报告与运行记录必须携带按角色的明细 | P0 | `TestReportCarriesPerRoleBreakdown` |
| FR-009 | 部分定价的运行必须报告已定价的那部分，并指出哪些未定价 | P1 | `TestPartiallyPricedRunIsExplicit` |
| FR-010 | `mas doctor` 必须报告哪些模型已定价、哪些未定价 | P1 | doctor 测试 |
| FR-011 | `mas models` 必须列出实际生效的路由：每个角色将使用哪个 provider 与哪个模型 | P1 | CLI 测试 |
| FR-012 | 按角色的路由必须体现在运行记录中，以便复现一次比较 | P1 | `TestRunRecordCarriesRouting` |

## 5. 非功能需求

| ID | 需求 | 度量 |
|---|---|---|
| NFR-001 | 不影响确定性：相同输入与相同路由产出相同报告 | 既有确定性测试，外加路由 |
| NFR-002 | 不引入新的模块依赖 | `go.mod` 无变化 |
| NFR-003 | 价格是数据而非代码：新增一条价格无需重新编译 | 配置测试 |
| NFR-004 | 每一个面向运维人员的字符串都双语对等 | `sddctl verify` |
| NFR-005 | 按角色 provider 的凭据脱敏方式与默认 provider 完全一致 | 脱敏测试 |
| NFR-006 | 在会并发运行角色的拓扑下，核算必须正确 | `-race`、并发拓扑测试 |

## 6. 约束

| ID | 约束 | 来源 |
|---|---|---|
| CON-001 | 未知的成本绝不被渲染成数字 | 宪法第五条，如实报告 |
| CON-002 | 本项目不内置任何价目表 | 第九条：一个看似权威的过期数字就是一句假话 |
| CON-003 | 路由不得改变某个角色被允许做什么 | 第四条：护栏不受"跑的是哪个模型"影响 |
| CON-004 | 成本绝不得成为安全的闸门 | 见上文范围外 |

## 7. 验收

当某个角色可以被路由到不同的 provider、已定价的运行能按角色报告其成本、
未定价的运行以两种语言明说而不是显示 0、`mas models` 能展示生效路由，
且 `make ci` 全绿时，本特性完成。
