# 实施计划：Case 语料库与评测框架

> **特性 ID**：`006-eval-harness` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`plan.md`](./plan.md) · **上游**：[`spec.zh.md`](./spec.zh.md) v1.0.0 · **下游**：[`design-hld.zh.md`](./design-hld.zh.md)

## 1. 决定其余一切的那个决策

**"什么算正确"必须无需人工判断即可检查。**

诱人的做法是拿报告的散文与参考答案做相似度打分。它诱人，是因为看起来像在度量"理解"；
而它是错的，且错因彼此叠加：它奖励复述提示词的模型；
它让每一个新 case 都需要一位参考答案撰写者；
它给出一个没人能精确说明其含义的数字 —— 而这恰是本项目宪法一贯最坚决拒绝的性质。

因此语料库标注的是**系统本就以受控词表提交的事实**：

- **得出了哪个故障模式** —— 各知识包的 failureMode id；
- **绝不应得出哪些模式** —— 那些看似合理的错误答案；
- **必须声明哪些缺口** —— 当 case 刻意扣留某个源时。

三者都是 id，三者都已由流水线产出，
针对它们的打分器无需人工判断、也无需参考文本。
代价是这个语料库无法度量"解释得**有多好**"。这是一个真实的局限，
文档会直说，而不是假装那个数字把它也涵盖了。

## 2. 设计决策

| ID | 决策 | 理由 | 反转条件 |
|---|---|---|---|
| D-1 | 只对流水线本就产出的 id 打分 | 需要人工判断的打分器无法在 CI 中运行；而基于相似度的打分器度量的是错的东西 | 出现了一种没有 id 的结论类型 |
| D-2 | 框架起的是桩 Prometheus 与 Loki 的 **HTTP 服务端**，而不是注入桩工具 | 注入工具会绕过采集器客户端、护栏与查询构造 —— 而这些恰是最可能回归的部分。一个绕过真实路径的框架，度量的是没人在跑的那个系统 | — |
| D-3 | 不给出单一的压缩分数 | 正确性、错误结论、成本与时延彼此权衡，加权求和等于替读者悄悄做了这个权衡 | — |
| D-4 | 错误结论与漏判分开计数 | "什么都没说"与"自信地说错了"是两种不同的失败、代价不同；把它们平均在一起会掩盖某次改动到底造成了哪一种 | — |
| D-5 | mock provider 的运行只报告确定性阶段，并拒绝把 Agent 阶段当作模型质量呈现 | mock 重放的脚本里本就写着答案。把它当作模型得分来报告，会是可能范围内最讨喜的一句谎话 | — |
| D-6 | case 内置随包发布，同时可加载额外目录 | 与知识包同一条规则：运维人员拥有自己的语料库才是要点，而一个无法扩展的内置语料库只是演示 | — |
| D-7 | "语料库是合成的"这条限定由渲染器输出，而不是丢给文档 | 写在手册里的限定，在有人截图那张表的那一刻并不在场 | — |

## 3. 风险

| ID | 风险 | 缓解 |
|---|---|---|
| RSK-001 | 语料库变成靶子，知识包被朝它拟合 | 规格中已列为范围外，文档中也写明：被用来拟合的语料库就不再是度量。case 断言的是**结论**而非阈值，因此为迎合 case 而拟合的知识包，仍然必须在机理上是对的 |
| RSK-002 | 合成语料库被读成准确率 | 该限定与每一次结果一同渲染、两种语言都有，且全程不使用"准确率"一词 |
| RSK-003 | 桩服务端与真实 Prometheus/Loki 的返回逐渐脱节 | 它们提供的 JSON 形态与采集器测试所断言的完全一致，而那些测试仍是形态的唯一真相来源 |
| RSK-004 | 语料库拖慢 CI，直到有人把它删掉 | NFR-001 规定确定性 provider 下整个语料库上限 60 秒，且运行器在 case 之间并发 |
| RSK-005 | 某个 case 因为"蒙对"而通过 | 每个 case 都声明它**绝不应**得出的模式，因此一个"什么都下结论"的拓扑会失败而不是得高分 |

## 4. 阶段

| 阶段 | 内容 | 闸门 |
|---|---|---|
| A | case schema、语料库加载器、双语校验 | case 能加载；无预期结果的 case 被拒 |
| B | 桩遥测服务端；跑在真实 service 之上的运行器 | FR-003 —— case 经真实流水线抵达结论 |
| C | 打分：命中、错误结论、缺口；确定性 | FR-004、FR-005、FR-006、FR-008 |
| D | 矩阵、渲染、限定声明、`mas eval` | FR-007、FR-010、FR-011、NFR-005 |
| E | 内置语料库，每个知识包一个 case；CI 闸门；文档 | FR-012、FR-013、`make ci` |
