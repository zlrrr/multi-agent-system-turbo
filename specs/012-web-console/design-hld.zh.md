# 高层设计（HLD）：只读 Web 控制台

> **特性 ID**：`012-web-console` · **版本**：1.0.0 · **状态**：已批准
> **双语对照**：[`design-hld.md`](./design-hld.md) · **上游**：[`plan.zh.md`](./plan.zh.md) v1.0.0 · **下游**：[`design-lld.zh.md`](./design-lld.zh.md)

## 1. 它在什么位置

```
  浏览器
    │  GET /ui/            （匿名：html、css、js、strings.json）
    ▼
  ┌──────────────────────────────────────────────────────────┐
  │  控制台资源 —— 内嵌、静态、白名单                          │
  └──────────────────────────────────────────────────────────┘
    │
    │  fetch(..., {headers: {Authorization: "Bearer …"}})
    ▼
  ┌──────────────────────────────────────────────────────────┐
  │  授权器（009）──► Principal ──► MayReach（011）            │
  └──────────────────────────────────────────────────────────┘
    │
    ▼
  GET /api/v1/diagnoses · /diagnoses/{id}[?steps=true]
      /targets · /topologies · /packs · /
```

控制台位于授权器**之下**，而不是与之并列。从资源处理器到 service 没有任何一条箭头，而这个
"没有"正是设计本身：控制台显示的一切，都要穿过 `curl` 所穿过的同一道守卫，因此 scope 与租户
只被执行一次，而不是两次。

服务端的全部贡献就是最上面那个方框 —— 四个它二进制里已经带着的文件 —— 外加 API 索引上的
一个新字段。

## 2. 外壳匿名；数据不匿名

浏览器导航到某个页面时无法附加 `Authorization` 头。任何普通导航都不能。于是只剩两种形状：

| 形状 | 代价 |
|---|---|
| 登录端点发放 Cookie | 一个会话存储、每条改状态路由上的 CSRF 防护、一套需要与既有方案保持同步的第二认证方案，以及一个浏览器会自动附加到每个请求上的凭据 |
| 匿名外壳，凭据手工输入，以请求头发送 | 服务端不新增任何东西；就是既有的 Bearer 方案，从 JavaScript 里用 |

我们选第二种。匿名提供出去的是：不含数据的 HTML、一个样式表、一个脚本，以及一张两种语言的
UI 标签表。它披露了"MAS-Turbo 正在运行"这一点 —— 而 `/healthz` 早已披露 —— 除此之外别无
其他：没有目标名、没有运行记录、没有环境版本、没有租户。

运维粘贴凭据；它在该标签页的 `sessionStorage` 中保存，并在每次 `fetch` 时以
`Authorization: Bearer` 发送。关掉标签页即告结束。它绝不进入 URL —— URL 会进访问日志、
浏览器历史和 Referer 头 —— 也绝不进入 Cookie，因为浏览器自动发送的凭据需要 CSRF 防护，
而 Bearer 头不需要。

在非 loopback 的明文来源上，控制台会在接受任何输入之前先把这件事说出来。`httpapi.Admit`
本来就拒绝在无 TLS、也未声明有终止代理的情况下把带凭据的 API 绑到非本机；这条横幅只是把
同一条规则，重述在敲键盘的人看得见的位置。

## 3. 双重只读

按宪章，本系统对环境是只读的。控制台对**系统本身**也是只读的：它渲染已经算出来的东西，
不提供任何发起诊断的入口。

这是刻意收窄，不是疏漏。发起诊断会花掉模型 token 并读取生产遥测，它需要 `diagnose` scope。
浏览器标签页是安放这种凭据的糟糕地方：容易被人从肩后看到，会被粘贴到当时开着的任何窗口里，
而一个能花钱的控制台，就是一个总会有人忘记退出的控制台。`diagnose` 仍然是机器对机器的
scope，由 CLI、CI 以及运维自己写的自动化持有。

控制台需要的是 `read`，而 `read` 正是一个状态页面应该拥有的 scope。

## 4. 报告正文是不可信输入

控制台要渲染的报告里包含：

- 由语言模型撰写的摘要与逐条假设的推理，
- 从环境中摘出来的日志行与错误串，
- 由发起者手工输入的目标名、症状与备注。

没有一样是我们控制的。若控制台把其中任何一项变成 HTML，它就是一个存储型 XSS 入口 ——
凡是能在被监控服务器上写下一行日志的人都能触达，而在中间件主机上，这几乎就是所有人。

所以控制台压根不从数据生成 HTML。元素被创建出来，然后设置它的 `textContent`；响应中的任何
字符串都不会被当作标记解析。那些有可能做出别的事的注入点 —— `innerHTML`、`outerHTML`、
`insertAdjacentHTML`、`document.write`、`eval`、`new Function` —— 在资源中不出现，并由测试
拒绝，使它们日后也无法出现。

严格的 `Content-Security-Policy` 作为纵深防御守在后面：`default-src 'none'`，脚本与样式
只允许 `'self'`，`connect-src 'self'`，不允许任何内联。代价是一个响应头，加上把 CSS 与
JavaScript 各自放在自己文件里的自律 —— 它们本来就该在那儿。

## 5. 诚实是一项渲染需求

本系统的产出不是一个答案。它是一组带排序的假设，每条有自己的置信度，依托的证据有时并不
完整，建议是仅供参考的，成本有时是未知的。控制台完全可以用一个大号字体和一个折叠区块把
这些细微之处全部毁掉 —— 而它看上去仍然像一个能用的控制台。

因此控制台把下列内容作为一等内容渲染，绝不藏在折叠之后：

| 内容 | 为什么不能折叠 |
|---|---|
| 每条假设的置信度与状态 | 55% 的"有证据支持"和 95% 的"有证据支持"是两种不同的主张 |
| 被否证的假设，保持可见 | 排除了什么，是"学到了什么"的一半 |
| 缺口，连同其错误码与影响 | 缺日志得出的诊断是一个带洞的诊断，而这个洞是值班读者最先需要知道的 |
| 每条建议上的"仅供参考" | 宪章第四条：本系统只建议，从不动手，读者不能有机会忘记这一点 |
| 未定价的模型与不完整的成本 | 说不知道的成本是诚实的；说是零的成本是谎言 |
| `truncated` 与备注 | 触到上限的运行，产出比它本可以产出的要少 |

## 6. 字符串住在 Go 里

控制台自身的标签是一张放在 Go 里的双语表，以 JSON 提供出去。它们本来也可以住在 JavaScript
里 —— 那样它们的配对性要么由一个 Go 测试去读 JavaScript 来检查，要么根本没人检查。

放在 Go 里，它们就能像错误码注册表那样被检查：每个 id 都必须两种语言齐备，否则构建失败，
而且测试读的是真正的那张表，不是它的副本。脚本里完全没有面向运维的正文 —— 它只引用 id ——
所以"这个控制台是不是双语的"这个问题，只有一个地方需要看。

语言按三步解析，每一步都比上一步更权威：

1. 浏览器自身的语言，这是在拿到任何凭据之前就能用的猜测；
2. 服务端配置的 `run.language`，在读到索引之后生效 —— 配置了中文的运维，想要的就是中文；
3. 阅读者的显式选择，它胜出，并在该标签页内一直有效。

## 7. 把它关掉

`server.ui.enabled` 默认开启。一个必须先发现某个配置项才能启用的控制台，就是没人用的控制台，
而"UI 能呈现报告"是本里程碑的退出条件之一。

不想要控制台的部署把它设为 false，此时 `/ui/` 返回 `MAS-7016`，而不是干巴巴一个 404 ——
手动敲进这个 URL 的运维值得知道原因和该改哪个配置项，而"控制台被关掉了"这件事本身并不值得
隐瞒。

`mas doctor` 会在 API 认证与租户状态旁边报告当前是哪一种，因为"控制台开着吗"通常和那两个
问题在同一口气里被问出来。

## 8. 本设计刻意不做的事

- **不做仪表盘**。NG-3 依然成立：本系统查询可观测性栈，它本身不是。控制台展示一次诊断；
  Grafana 展示时间序列。
- **不做配置编辑**。配置是一份经过评审的文件，而会写 YAML 的表单就是一个绕过评审的表单。
- **不引入框架与构建步骤**。打包器会给一个交付故事是"一个静态二进制加一个容器"的仓库塞进
  一整条工具链，而这个界面并不需要。
- **不用 WebSocket**。进行中的运行只在其详情视图打开时被轮询，那是一个 `setTimeout`，
  不是一个协议。
