> **特性 ID**：`012-web-console` · **版本**：1.0.0 · **状态**：已批准
> **双语对照**：[`spec.md`](./spec.md) · **上游**：[`docs/zh/project-goals.md`](../../docs/zh/project-goals.md) v1.2.2
> **宪章**：`.specify/memory/constitution.md` v1.0.0 · **下游**：`plan.md`

## 1. 问题陈述

一次诊断就是一份文档。它有摘要、按置信度排序的假设及其推理、发现、这些结论所依据的证据、
证据缺失之处的缺口，以及仅供参考的处置建议。`mas diagnose` 把它渲染成 Markdown，API 把它
返回成 JSON —— 对亲自跑这条命令的人来说，两者都是正确答案。

对其他所有人来说，两者都不是。凌晨三点的值班工程师手上只有聊天消息里的一个 run id，没有
打开的终端。团队负责人想知道这一周诊断了什么，但不想为此去学 `jq`。追问"它到底看了哪些
东西"的复盘者想读步骤轨迹，而那是一个很大的 JSON 数组。

`NG-6` 当初刻意推迟了 UI：在一个只做了一半的 API 之上做控制台，等于把控制台重做三遍。那个
理由现在已经失效。API 如今能认证、能按 scope 授权、能按租户切分、能持久存储运行记录 ——
控制台可以做成它的**客户端**，而不是它的第二套实现。

这个特性带来的风险不是复杂度，而是不诚实。一份渲染出来的报告很容易显得比它本身更确定：
一句自信的话配上大号字体，把缺口折叠起来，把"仅供参考"排成灰色小字。本系统产出的诊断，
本质是一组带置信度、带已知缺口的假设，控制台必须把它照原样呈现，否则还不如没有控制台。

## 2. 用户与场景

| 角色 | 目标 | 触发场景 |
|---|---|---|
| 值班工程师 | 只凭一个 run id，从手机或浏览器标签页读完一次诊断 | 故障期间，任何时刻 |
| 团队负责人 | 不开终端就能看到诊断了什么、是怎么推理的 | 每周复盘 |
| 复盘者 / 审计 | 阅读步骤轨迹：跑了哪些工具、返回了什么、哪些失败了 | 故障之后 |
| 加固部署的运维 | 干脆不提供控制台 | 部署评审 |
| 中文运维 | 用中文阅读控制台 | 每天 |

## 3. 范围

### 范围内
- 由 `mas serve` 在 `/ui/` 提供的 Web 控制台，资源内嵌，无构建步骤，无新增模块依赖。
- 视图：运行列表、运行详情（摘要、假设、发现、证据、缺口、建议、用量与成本）、步骤轨迹、
  目标列表、系统视图（知识包、拓扑、版本、健康）。
- **只读**：控制台渲染已经算出来的东西，不能发起诊断。
- 沿用既有 Bearer 凭据认证，由运维手工输入，仅在该浏览器会话内保留。
- 双语，字符串表像错误码注册表一样接受配对检查。
- 失败按 `MAS-NNNN` 错误码、消息与处置建议渲染。
- 一个可以不提供控制台的配置项，以及 `mas doctor` 对当前状态的报告。

### 范围外
- **从浏览器发起诊断**。它会花掉模型 token 并读取生产遥测，有权做这件事的凭据不该是浏览器
  标签页里握着的那一个。`diagnose` scope 仍然是机器对机器的凭据。
- **任何针对环境的动作**。宪章第四条：这里没有任何东西会写入任何地方，控制台和其他任何
  API 读者一样只是读。
- **Cookie、会话或登录端点**。没有 Cookie 就没有 CSRF，也没有服务端会话状态；控制台复用
  API 已有的 Bearer 方案。
- **JavaScript 框架、打包器或包清单**。NFR-001 禁止这类依赖，而这个界面也并不需要。
- **在服务端渲染环境数据**。第二条数据通路就是第二个会忘记租户过滤的地方；每一个字节的
  环境数据都要走那条受守卫的 API。
- **原始遥测图表**。控制台展示的是诊断，不是仪表盘 —— Grafana 已经存在，NG-3 依然成立。
- **编辑配置**。配置是一份接受评审的文件，而不是一个表单。

## 4. 功能需求

| ID | 需求 | 优先级 | 验收信号 |
|---|---|---|---|
| FR-001 | `mas serve` 必须在 `/ui/` 提供 Web 控制台 | P0 | `TestConsoleIsServed` |
| FR-002 | 控制台静态资源必须无需凭据即可响应，而所有数据通路必须仍然受守卫 | P0 | `TestConsoleShellIsAnonymousAndDataIsNot` |
| FR-003 | 不得在受权 API 之外提供任何环境数据 | P0 | `TestConsoleServesNoEstateData` |
| FR-004 | 控制台不得能够发起诊断 | P0 | `TestConsoleNeverStartsADiagnosis` |
| FR-005 | 控制台不得把数据写成 HTML：不使用 `innerHTML`、`document.write`、`eval` | P0 | `TestConsoleNeverUsesAnHTMLSink` |
| FR-006 | 控制台响应必须携带严格的 Content-Security-Policy，且不使用内联脚本与内联样式 | P0 | `TestConsoleSendsAContentSecurityPolicy` |
| FR-007 | `/ui/` 下必须只提供白名单内的资源 | P0 | `TestConsoleServesOnlyItsOwnAssets` |
| FR-008 | 控制台的每一条字符串都必须两种语言齐备 | P0 | `TestConsoleStringsAreBilingual` |
| FR-009 | 控制台引用的每个字符串 id 必须存在，字符串表中的每一项也必须被引用 | P1 | `TestConsoleStringsAreAllUsed` |
| FR-010 | 请求失败时必须渲染其错误码、消息与处置建议 | P0 | `TestConsoleRendersTheErrorCode` |
| FR-011 | 凭据不得出现在 URL、Cookie 或持久化存储中 | P0 | `TestConsoleKeepsTheCredentialOutOfURLsAndCookies` |
| FR-012 | 缺口、"仅供参考"标记与未定价成本必须被渲染出来，而不是被隐藏 | P0 | `TestConsoleSurfacesGapsAndAdvisoryStatus` |
| FR-013 | 控制台必须可以关闭，且关闭时必须说明 | P1 | `TestConsoleCanBeDisabled` |
| FR-014 | API 索引必须报告服务端配置的语言 | P1 | `TestIndexReportsTheLanguage` |
| FR-015 | `mas doctor` 必须报告控制台是否在提供服务 | P1 | `TestDoctorReportsTheConsole` |

## 5. 非功能需求

| ID | 需求 | 度量 |
|---|---|---|
| NFR-001 | 不新增模块依赖，不引入构建步骤 | `go.mod` 不变；无 `package.json` |
| NFR-002 | 每一条面向运维的字符串都是双语 | `TestConsoleStringsAreBilingual`、`sddctl verify` |
| NFR-003 | 控制台不给 API 的请求路径增加任何东西 | 资源是静态的；没有任何处理器需要询问控制台 |
| NFR-004 | 资源随二进制与容器镜像一起发布 | `//go:embed`；`mas serve` 不需要磁盘上的文件 |
| NFR-005 | 整个控制台小到可以读完 | 全部资源合计 1500 行以内 |

## 6. 约束

| ID | 约束 | 来源 |
|---|---|---|
| CON-001 | 只读：不对任何环境执行任何动作 | 宪章第四条 |
| CON-002 | 单一收口点：控制台不获得任何绕过授权器的数据通路 | 第七条第 2 款；特性 009 与 011 |
| CON-003 | 报告正文是不可信输入 —— 它来自模型，也来自环境日志 | §1 |
| CON-004 | 每条字符串都要两种语言 | 第三条 |
| CON-005 | 不确定性要被展示出来，绝不被抹平 | 第四条；`docs/zh/project-goals.md` G12 |

## 7. 验收

当运维可以打开 `/ui/`，粘贴一个 read 凭据，看到本租户可见的运行记录，打开其中一条，用任一
语言读到它的摘要、带置信度的假设、发现、证据、缺口与仅供参考的建议；当步骤轨迹只隔一次
点击；当失败会显示自己的 `MAS-NNNN` 错误码；当加固部署可以把整个控制台关掉；并且 API 的
授权、租户与只读姿态没有因此发生任何变化 —— 本特性即完成。
