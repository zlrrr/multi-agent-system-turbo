# 实施计划：回归基线与模型维度

> **特性 ID**：`008-regression-baselines` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`plan.md`](./plan.md) · **上游**：[`spec.zh.md`](./spec.zh.md) v1.0.0 · **下游**：[`design-hld.zh.md`](./design-hld.zh.md)

## 1. 思路

代码本身只是对特性 006 已经产出的结果做算术。需要决定的是：**基线到底是什么**，
因为最显而易见的那个答案，恰恰是会腐坏的那个。

**显而易见的答案：记录数字。** 按拓扑存下命中数与漏判数，比较总数，
总数变差就失败。第一个例子就足以否决它：一次"用漏判换错误结论"的改动，
会让总数完全不变。语料库当初就是为了"这两类失败永不相加"而建的，
而一个把它们相加的基线，等于从外部把这件事推翻。

**我们记录的是：每个格子的结果，以类别的形式。** 一个格子是一组（case、拓扑、模型）。
它的类别是 `hit`、`miss`、`wrong`、`gap-missed` 或 `error`，
外加造成该结果的那些 id。于是比较就是逐格的状态转移，
而这些转移都有运维人员一看就懂的名字：修好、回归、失败方式改变、新增、未运行。
没有任何东西被抵消，因为没有任何东西被相加。

这个选择让 FR-004 自然成立，而不需要额外机制：
一个原本是 `miss`、现在仍是 `miss`、且 id 完全相同的格子，不构成一次转移。
它会让绝对闸门失败，却能通过基线闸门 ——
而这恰恰是"不必为了让 CI 变绿而删掉一个已知为坏的 case"所需要的行为。

**模型维度就是同一个矩阵多一维。** `Runner.Matrix` 已经在做 case × 拓扑的叉乘；
再叉乘上模型是同一个循环、同一套 `Options`，只是逐个作业地变化模型。
有意思的不是这个循环 —— 而是每个格子必须携带产出它的那个模型，
否则记账就会把成本归到"最后一次恰好被配置"的那个模型头上。

## 2. 设计决策

| ID | 决策 | 理由 |
|---|---|---|
| D-1 | 基线记录逐格的结果类别与 id，绝不记录总数 | 对于本项目专门拒绝去平均的那类交易，总数可以完全相同 |
| D-2 | 一个格子是（case、拓扑、模型） | 比这更粗就回答不了"是哪个模型回归了"；比这更细则没有意义 |
| D-3 | 比较给出的是状态转移，而不是差值 | "回归"与"改善"是两件不同的事；一个带符号的数字会把它们变成一件 |
| D-4 | 同样的失败重复出现不算一次转移 | FR-004。这消除了"为了让 CI 变绿而删掉已知为坏的 case"这一激励 |
| D-5 | 基线只由 `--write-baseline` 写入 | 会自我写入的基线记录的是"发生了什么"，因此永远不会失败（CON-003） |
| D-6 | 基线携带其记录时的 provider 与模型；不匹配时予以披露，而不是拒绝比较 | 跨模型比较正是模型矩阵的意义所在；而隐瞒"这次比较跨了模型"就不是了 |
| D-7 | JSON，键有序，每格一份结构 | FR-012：没人能 diff 的基线，就是没人会评审的基线 |
| D-8 | 发布的基线在确定性 provider 下记录 | 一个每次运行都会变的文件不是基线（§3） |
| D-9 | 每一次比较都声明每格只是一个样本 | 在真实模型下，一个格子是一次抽样而不是一次测量，读者必须知道自己在看哪一种 |

## 3. 风险

| ID | 风险 | 缓解 |
|---|---|---|
| RSK-1 | 基线沦为橡皮图章：靠重写基线来接受回归 | 写入是显式的，文件可 diff 且很小，转移报告会列出每一处变化，使评审有东西可看 |
| RSK-2 | 已知为坏的格子因为不再让 CI 失败而被遗忘 | 比较结果每次运行都会列出已知为坏的格子，而不只在它们变化时才列 |
| RSK-3 | 有人把"每格一个样本"的模型比较当成基准测试 | 见 D-9；并且该限定声明会像特性 006 那样以字段形式随 JSON 一同传递 |
| RSK-4 | 模型维度悄悄把成本归错了模型 | 格子自带其模型；测试断言的是逐格记账而不是整次运行的记账 |

## 4. 实施顺序

1. `Cell` 与 `Baseline`：记录本身、稳定编码、加载与保存。
2. `Compare`：状态转移，回归与改善分开。
3. 基线闸门，与绝对闸门并存。
4. `Runner.Matrix` 中的模型维度，带逐格记账。
5. 渲染：转移、已知为坏的格子，以及抽样限定声明。
6. `mas eval --baseline / --write-baseline / --models`；发布基线；CI。
