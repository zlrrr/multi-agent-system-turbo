# 特性规格：基于对象存储的共享持久化运行存储

> **特性 ID**：`010-object-run-store` · **版本**：1.0.0 · **状态**：已批准
> **双语对应文件**：[`spec.md`](./spec.md) · **上游**：[`docs/zh/project-goals.md`](../../docs/zh/project-goals.md) v1.2.0
> **宪法**：`.specify/memory/constitution.zh.md` v1.0.0 · **下游**：`plan.zh.md`

## 1. 问题陈述

运行记录就是审计轨迹。G1.4 要求每一次运行事后都可复现、可审计，
而 `mas replay` 做到了这一点 —— 前提是从某一台机器磁盘上的一个目录里读。

这对笔记本足够，但对这个服务真实的部署方式来说是错的。
在 Kubernetes 中，文件系统通常属于 Pod，因此一次重启就会丢掉历史；
而 `mas serve` 的第二个副本看不到第一个副本的运行记录，
于是 `GET /api/v1/diagnoses` 的回答会取决于哪个 Pod 接到了请求。
一份有一半副本看不到的审计轨迹，不是审计轨迹 —— 那是一个附带承诺的缓存。

`RunStore` 这条缝自 M1 起就已就位，因此这里不改变"一次运行是什么"。
缺的是一个既持久又**共享**的后端，而且要以目标环境本就具备的形态提供：对象存储。

## 2. 用户与场景

| 角色 | 目标 | 触发时机 |
|---|---|---|
| 平台工程师 | 跑多个副本，并让它们对历史的看法一致 | 从一个 Pod 扩容出去时 |
| SRE | 在产出它的那个 Pod 早已消失之后，重放上个月的一次运行 | 故障复盘 |
| 审计人员 | 用存储自身的保留策略与访问控制去读取这份轨迹 | 合规问询 |
| 开发者 | 继续用一个目录，不需要桶，也不需要凭据 | 每天 |

## 3. 范围

### 范围内
- 一个 **S3 兼容**的运行存储：AWS S3、MinIO、Ceph RGW，
  以及任何说同一套子集协议的实现。
- **SigV4** 请求签名，依据公开规范实现，并用其公开测试向量验证。
- 步骤以**不可变对象**写入，使"只追加"这一性质在没有 append 的后端上依然成立。
- 从进程死亡前已写入的内容中，**重建被中断的**运行。
- 按最新优先、有上限地列举，且无需下载每一条记录。
- 一个 `mas doctor` 探测，说明该桶是否可达、是否可写。
- 双语错误与文档。

### 范围外
- 关系型或嵌入式数据库。每一种选项都需要引入依赖，
  而手写一个，就是让"并不在写数据库的人"去写一个数据库。
- 服务端加密、对象锁定、生命周期规则、版本控制。
  它们都属于桶策略，运维人员在配置桶的地方配置它们。
- 把已有的文件系统存储迁移进桶。复制目录是复制目录的工具该做的事。
- 对**进行中**运行的跨副本协调。多个副本不共享一次正在进行的诊断；
  它们共享的是已完成运行的记录。
- 从实例元数据或 `~/.aws` 获取凭据。
  凭据是配置 —— 与本项目其他每一处一致。

## 4. 功能需求

| ID | 需求 | 优先级 | 验收信号 |
|---|---|---|---|
| FR-001 | `store.type: s3` 必须完整满足 `RunStore` 接口 | P0 | `TestS3StoreSatisfiesTheContract` |
| FR-002 | 请求必须以 SigV4 签名，并与公开测试向量一致 | P0 | `TestSigV4MatchesPublishedVectors` |
| FR-003 | 步骤一旦写入，绝不得被重写 | P0 | `TestStepsAreWrittenAsImmutableObjects` |
| FR-004 | 在完成之前被中断的运行，必须能从已写入的内容中重建 | P0 | `TestInterruptedRunIsReconstructed` |
| FR-005 | `List` 必须按最新优先、有上限返回，且无需读取每一条记录 | P0 | `TestListIsNewestFirstAndBounded` |
| FR-006 | 存储下来的记录必须携带与文件系统存储相同的完整性摘要 | P0 | `TestDigestSurvivesTheRoundTrip` |
| FR-007 | 存储失败必须以带错误码的形式浮现，绝不得被静默吞掉 | P0 | `TestStorageFailuresAreCoded` |
| FR-008 | 当存储在分析完成之后失败时，报告仍必须被返回 | P0 | `TestRunSurvivesAStoreFailure` |
| FR-009 | 凭据必须是密钥，绝不被打印或记入日志 | P0 | `TestObjectStoreCredentialsAreNeverEchoed` |
| FR-010 | path-style 与 virtual-host 两种寻址方式都必须可用 | P1 | `TestBothAddressingStylesAreSupported` |
| FR-011 | `mas doctor` 必须报告该桶是否可达、是否可写 | P1 | `TestDoctorProbesTheObjectStore` |
| FR-012 | 配置必须在加载时校验，而不是等到第一次写入 | P0 | `TestObjectStoreConfigIsValidatedAtLoad` |
| FR-013 | 文件系统存储与内存存储必须保持原样可用 | P0 | `TestExistingStoresAreUnchanged` |

## 5. 非功能需求

| ID | 需求 | 度量 |
|---|---|---|
| NFR-001 | 不引入新的模块依赖 | `go.mod` 未变 |
| NFR-002 | 每一条面向运维人员的字符串都是双语 | `sddctl verify` |
| NFR-003 | 一次已完成的运行必须能用一次 GET 读出 | 结构性测试 |
| NFR-004 | 任何测试都不得触及真实网络 | 仅使用 `httptest` |

## 6. 约束

| ID | 约束 | 来源 |
|---|---|---|
| CON-001 | 无论后端是什么，一次运行内部都只追加 | LLD §2.14、G1.4 |
| CON-002 | 丢失的记录必须被报告，绝不被隐藏 | 宪法第九条 |
| CON-003 | 凭据是密钥，绝不被渲染出来 | 第八条 |
| CON-004 | 每条消息都要有两种语言 | 第三条 |
| CON-005 | 签名依据规范实现，并用其测试向量证明 | §3、FR-002 |

## 7. 验收

当满足以下条件时，本特性完成：一个桶可以承载运行记录；
指向同一个桶的两个进程看到相同的历史；
一次中途被打断的运行仍可被读回；存储失败是一个带错误码的错误而不是一次静默丢失；
没有任何凭据进入日志；且文件系统存储丝毫未被触碰。
